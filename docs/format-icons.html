「输出格式」图标候选 · 画出来

这次是格式语义：图标要说出"答案以什么形态交给你"。每枚都放在 42px / 26px 按钮（关·开）/ 14px 三档尺寸下看，并给出 14px 可读性判定。
关键差别（和上一批"网页图标"比）：表达"格式"时，图标需要构成一对——因为格式是二选一。 所以真正要挑的不是一枚图标，而是 「文字侧」+「网页侧」的配对：两者在 14px 下必须是两种不同轮廓 （细横线 vs 有边框的块），才能一眼看出"现在是哪一档"。下面第二节就是配对实测。

① 文本行 ≡
纯文字的行业符号
 三根横线 = "就是文字"。通用度最高，和"有边框的块"对比强烈，缩到 14px 依然是细线。 强
② 段落符 ¶ 排版界老符号，专业感强；14px 下容易看成一个"P"或一团线。 弱
③ Markdown ↓M 开发者一眼懂；但我们的"文字档"包含普通段落，Markdown 是子集，容易过窄。 弱
④ 代码 </> 表示"代码/源码"。风险：我们的输出是渲染好的网页，不是源码，会误导成"给我看代码"。 中

⑤ 网页窗口 ▭ 网页侧的行业符号。轮廓是"块"，和文本侧的"细线"对比最强。 强
⑥ 版面页 ▤ 窗口里带版块——除了"网页"还说清"我给你排版"。14px 下版块会变小但仍成块。 中
⑦ 表格 表示"表格/表格化输出"。我们的网页常常是表格+图，但表格只是一部分。 中
⑧ 档位滑杆 表示"在几档之间切换"这件事本身，不指向具体格式。适合做"格式"这个概念的图标，不适合表示网页。 中
⑨ 两段胶囊 "二选一"的抽象符号，和控件本身的形状同构（我们做成分段开关时它就是控件本身）。 中
⑩ 转换箭头 ⇄ "换一种形式"。语义对，但它描述的是动作，放在"当前是哪一档"的位置上会失焦。 中

结论：
① 表示"格式"本身的图标只有抽象那几个（⑧档位滑杆、⑨两段胶囊、⑩转换箭头），它们说明"可以换形态"，但说不出是哪两种形态。
② 表示"具体格式"的可用图标：文字侧 = ≡ 文本行（14px 强）、次选 ¶；网页侧 = ▭ 窗口（14px 强）、次选 ▤ 版面页；</> 和 Markdown 都偏"源码"语义，不建议。
③ 所以真正推荐的是配对 P1「≡ 文字 ｜ ▭ 网页」：两种轮廓差异最大（细线 vs 方框）、都带文字、零歧义，宽约 130px。
④ 如果嫌宽 → P4 纯图标版（约 70px），代价是新用户要 hover 才知道；如果面板更挤、宁可多点一次 → 上一批的 C「格式：文字 ▾」 最省地方。
