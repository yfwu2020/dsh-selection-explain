划词解读小窗的入口按钮，以前是贴着选区右上方出现的。问题是：当你在段落中间往左上拖选时，光标停在左上，按钮却跑到右上——眼睛得先找它。

如果把位置改成跟着最后一次鼠标位置走，按钮就出现在你松手的地方附近，视线不用移动。但要注意别盖住光标，也别压住刚选中的字。

动效上，scale + 透明度 是最常见的一档；带一点过冲（先放大到 106% 再回落）会更"弹"，但如果过冲太多、时长太长，连续划选时会显得拖沓。

提示：从下往上拖时按钮更适合放在光标上方；从上往下拖时放在下方——这样可以顺着拖拽方向，不挡住你刚划过的内容。

各定位策略的取舍

策略优点代价 / 风险
选区右上方（现状）位置稳定可预期，永远贴着文字往左上拖选时按钮离光标很远，视线要跳
鼠标上方居中顺着手，视线不用移靠近视口顶部时要翻到下方；多重选择（双击词）时鼠标可能不在选区附近
鼠标下方居中不挡光标上方内容靠近底部要翻上去
光标右下角最不遮挡：既不压光标也不压已选文字贴右下时可能出界，需要夹回视口
跟随拖拽方向顺着动作：往上拖放上边、往下拖放下边逻辑要解释；双击选词时没有方向，要有默认值
鼠标与选区中点兼顾"贴着文字"和"贴着手"长选区时位置偏怪，可能落在无关区域
鼠标优先 + 防遮挡两全：默认顺手，撞到选区就退到选区上方规则最多，行为偶尔会"变"（需要在文档里写清）
怎么用：在上面文档里划一段 → 按钮会按当前策略浮现 → 换策略/调参数，再划一次；想反复看动效就点「▶ 重播动效」。
我的建议：位置用 光标右下角（14px） 或 跟随拖拽方向，动效用 spring（过冲 12~16%、240ms、缩放原点跟锚点） —— 手感"弹"但不拖沓；时长超过 ~300ms 连续划选会开始觉得慢。
