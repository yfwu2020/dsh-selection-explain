小窗 composer · 模型与推理等级（UI 预览）

按主会话那套（模型名 · 等级 ⌄）搬进小窗工具行。全部 1:1、可点：点胶囊会向上弹出菜单，选项能真的切换。
可用空间：工具行总宽 516px，现在左边是「输出偏好」(≈117px)、右边是发送键 (26px) —— 中间空着 ≈350px，放一个 100~140px 的模型控件绰绰有余。
菜单方向：composer 贴着面板底部，所以菜单一律向上弹（下图都能点开看）。
先说清楚哪些能真做：host 现在已经接受 body.effort（首轮/详解生效），但追问档写死了配置值、 模型不可覆盖。所以要落地这个控件，host 需要各改一行（见页面底部"实现代价"）。

三、实现代价（诚实版）

要什么host 现状需要改什么
推理等级可改 已接受 body.effort，但**追问档**走 chatReasoningEffort，body.effort 被忽略 1 行：追问档优先用 body.effort（缺省才回配置）
模型可切换 路由由 agentDefaultModel.currentSelection() 决定，**不接受请求覆盖** 1~2 行：读 body.model/body.provider 覆盖（并做白名单校验）
可选模型清单 ctx.llm.listProviders() 已可用（现在只用来兜底取第一个） 在 ping 里多返回一个 models[]（含显示名/等级上限）
等级档位语义 off / low / high 已在用（首轮低、追问高） UI 上补一个"中"的映射即可（或只给 关/低/高 三档）
记住选择 localStorage 已在用（输出偏好） 同法各加一个 key
我的建议：A（单枚胶囊「V4.1 Flash · 高 ⌄」） —— 和主会话同构、一眼看全、约 128px 完全放得下；
如果你觉得"当前模型"不必常显、更在意省地方，就用 D（等级胶囊）：只露等级，模型收进菜单，74px。
不推荐 C（触屏看不见当前值）和 E（把高频/低频设置混在一起）。
