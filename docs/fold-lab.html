二、折叠规则（逐条）



  

    
<h1>…<h6>→ # … ######，层级原样保留

    
<p>→ 独立段落

    
<ul>/<ol>><li>→ -  / 1. ，嵌套按缩进

    
<table><tr><td>→ Markdown 表格（首行 + --- 分隔），行列一一对应

    
<pre><code>→ 代码块，超过 400 字截断并标注「…(已截断 N 字)」

    
<blockquote>→ > 

    
<strong><b> / <em><i>→ **…** / *…*（强调这一层语义不丢）

    
class / style 里的"高亮"→ 转成 **…**，并计入版式摘要

    
<a href> / <img alt>→ [文字](链接) / [图片: alt]（超长 URL 折叠）

    
<svg><canvas>→ [图示]（图形路径数据丢弃，位置保留）

    
<style><script><meta><link>→ 丢弃

    
display:none / hidden→ 丢弃（本来就不可见）

    
其它容器（div/section/main…）→ 继续下钻，不产生多余输出

  





三、真正的"无损"靠三条兜底



  

    
丢的东西兜底手段效果

    
颜色 / 字号 / 圆角 / 阴影 / 布局版式摘要一行（主色、明暗、分栏、高亮处数）模型仍知道"上一页长什么样"，改版式时不会瞎猜

    
完整可编辑的 HTML最近一轮保原样（只折叠更早的轮次）"把上面那张表的高亮改成蓝色"仍然可行

    
你看到的内容折叠只发生在"发历史"这一步面板里渲染的、代码视图里复制的始终是原文，一个字不少

  






  怎么实现的：一个纯函数 foldForHistory(text) —— 用 DOMParser 把 HTML 解析成 DOM，
  按上表递归遍历生成 Markdown；然后只在组装 history 时调用（ask() 里那一处 + 升格那一处），
  不碰 state.turns 里的原文。

  为什么敢说无损：看上面的「可见文本覆盖率」——它把原文 DOM 里所有可见文字抽出来，
  逐字检查是否都出现在折叠结果里；正常应接近 100%，缺的那些只可能是超长代码块的截断（会显式标注）。
