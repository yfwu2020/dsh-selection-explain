方案做法预览尺寸（实测推算）代价
A预览块撑满面板内容宽（负 margin 抵消气泡内边距 + 解除 90% 上限）445×240 → 510×240（+15%）气泡被"顶宽"，观感略变
B默认高度 240 → 320；「放大」档改成面板可视高度的 78%240 → 320（放大 ~400）两行 CSS，几乎无
C工具栏加「⛶ 全屏」→ 帧级浮层预览445×240 → ~1200×545（×6 面积）多一个浮层（Esc/定位/清理），~40 行
D给预览页注入 viewport + 轻量 reset（img/table max-width、body max-width）尺寸不变，但不再横向溢出（页面自己回流）往页面加几条基础规则（可加个开关）
E面板加宽档 540 → 720（内容有预览时自动）445 → ~620（×1.4），代码块/表格/详解同样受益动面板骨架，历史浮层定位/拖拽边界要重测
F预览块右下角拖拽改宽高自由最重（拖拽 + 记忆尺寸），~60 行

为什么"局促"主要是两件事

① 宽度被吃掉 95px：面板 540 → 消息区 497 → 气泡 471（90% 上限 + 左右各 11px padding）。

② 页面按宽屏设计：模型给的页面常按 1000~1200px 排版，塞进 445px 就横向溢出，只能左右拖——点 D 看回流后的差别。

推荐顺序

B + D 先做（低风险、立刻不那么局促）；A 再叠（+65px 宽）；想要"看得爽"再加 C。

E 是全局改善但动骨架，F 灵活但最重——你要长期用大量网页预览的话，E 比 F 划算。
