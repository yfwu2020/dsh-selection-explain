# 小窗网页设计规范

> 思路参考 Anthropic 公开的 `frontend-design` 技能（claude-code 仓库）与社区同类实践，按本插件
> 「约 500px 宽的窄容器」重写为中文规则。**这是给模型看的规范**：开启网页模式后，追问生成 HTML 时注入。

## 先决定"这页是什么"，再动手

- 先想清楚：**给谁看、要回答什么、第一眼该看到什么**。内容本身就是设计的来源——
  解释一个协议、对比两个方案、梳理一段流程，视觉应当各不相同，而不是套同一个壳。
- **页面本身就是回答**：不要再在页面外重复一遍文字答案，也不要在页面里复述问题。

## 硬约束（小窗形状决定的）

- **单列、宽度 100%**：不要固定像素宽度、不要 `min-width`、不要横向滚动；表格列数 ≤ 3，
  长内容允许换行（`word-break`）。小窗两侧已有 14px 内边距，页面自带 16–20px 内边距即可。
- **不要 `position:fixed` / `sticky` 头部**：容器会滚动，粘性元素会挡住内容。
- **不引外部资源**：不加载外部字体、CDN、图片；图示用内联 SVG 或纯 CSS 画。
- **一套主题**：浅色或深色只选一套（可用 `prefers-color-scheme` 覆盖，但默认给出明确底色）。

## 排版

- **一个字体家族就够**（最多两个，且要明显区分）；中文用系统字体栈即可，不要为了"高级"去引 Web 字体。
- 字号阶梯：主标题 20–22px、小标题 15–16px、正文 14px、辅助信息 12–13px；
  行高 1.6–1.75；**每行不超过约 30 个汉字**（窗口窄，这是天然上限）。
- 层级靠**字重与颜色**区分，不要靠一堆不同字号。

## 色彩

- **一个主色 + 一套中性灰阶**：主色用于强调与关键结论，灰阶承担 90% 的界面。
- 对比度按可读性底线来（正文与背景 ≥ 4.5:1）；深色页面别用纯黑，浅色页面别用纯白到底。
- 不要为了"丰富"给每个元素不同颜色。

## 结构即信息

- **只在内容真是序列时才编号**（步骤、时间线）；不是序列就别用 01/02/03 装饰。
- 对比用表格或左右并列；要点用列表；关键结论用一块高亮（左边框 + 淡底）。
- 卡片圆角、阴影**只给需要成组的内容**，不要所有东西都套同一个圆角同一层阴影。

## 避免这些"AI 味"默认值

以下都是生成式设计的常见套路，**不要无脑使用**（除非内容本身就该长这样）：

- 奶油底色 + 高对比衬线标题 + 陶土色强调；
- 近黑底 + 一个荧光绿/朱红强调；
- 发丝线 + 零圆角的"报纸式"密排；
- SaaS 卡片套件：什么内容都切成等宽圆角卡片，同一个圆角、同一层 `rgba(0,0,0,.1)` 阴影、再来点渐变当装饰；
- 每个标题上面都加一个全大写、加字距的小标签（eyebrow）；
- 用 `A · B · C` 把元信息串起来、标签写成 `词 — 短语`、伪黑 `#0B0B0B`、小号等宽字体当标签、链接和按钮结尾都跟一个 `→`。

**选一个地方出彩**就够了：让一个元素（标题的排法、一个内联图示、一处对比表）成为记忆点，
其余保持安静克制。

## 动效

- 只在"回应操作"（展开、切换、确认）或"一次入场"时用；不要每张卡片都 fade-in、不要每个卡片都 hover 抬升。
- 尊重 `prefers-reduced-motion`。

## 文案也是设计

- 主动语态、句子大小写；按钮写它会做什么（"保存修改"，不是"提交"）；同一个动作全流程同名。
- 说人话，不卖弄；错误要讲清发生了什么、怎么修；空白页要给出下一步。

## 交付前的自查

1. 缩到 360px 宽会不会横向滚动？
2. 主标题是不是唯一的第一视觉焦点？
3. 有没有哪一处是"任何题目都会这么写"的默认套路？换掉它。
4. 关掉样式后，HTML 结构读起来还通顺吗（语义标签、标题层级）？
